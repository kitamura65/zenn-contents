Claude Code の会話は、`~/.claude/projects/` にセッション1つにつき1ファイルで全文が残っています。ここを読めば「自分が実際に何を繰り返しているか」が分かるので、CLAUDE.md や Skill に何を書くべきかを勘ではなく実績で決められる——という話をちらほら見かけるようになりました。

自分も一度やっていて、そのときのメモには、42セッションぶん、プロンプト767件を読んだと書いてあります。先日それを記事にしようとして、同じ条件で数え直しました。

**36セッション・プロンプト537件。** 6日しか経っていないのに、230件ぶん合いません。

内訳を分けたら、こうなっていました。

| 差の理由 | プロンプト数 |
|---|---|
| 30日削除で実際に消えたぶん | 57 |
| 自分の抽出コードを直したぶん | 173 |

ログは既定30日で自動削除されるので「消えたんだな」で片付けるところでした。実際は**数え方の差のほうが3倍大きかった**。

追いかけているうちに、もう1つ分かったことがあります。**この「30日」はファイルの更新日時（mtime）で測られていて、会話の中身の日付ではありません。** なので「直近1ヶ月ぶんのログを見た」と言うとき、その1ヶ月は自分で選んだ期間ではないし、そもそも期間ですらない可能性があります。

同じことをやろうとしている人向けに、この2つの落とし穴を書きます。実際に使った抽出スクリプトも置いておきます。

## 前提：ログの置き場所と量

正確なパスは `~/.claude/projects/<パス由来のスラッグ>/<セッションID>.jsonl` で、中身は1行1JSONです。履歴から過去セッションを開けるのは、これを読んでいるからです。

手元は全部で40セッション・61.9MB でした（2026-08-25 時点。冒頭の36セッションは、最初に数えたときと同じ5プロジェクトに絞った数字です）。ツールの実行結果やファイルの中身が大半なので、自分が打ったプロンプトだけを抜くと 191KB・576件。1/332 になります。この量なら通しで読めます。

## 1. 減ったぶんの大半は、消えたのではなく数え方の違いだった

冒頭の内訳をどう出したかから書きます。

最初に数えたときのスクリプトは使い捨てにしていたのですが、幸いその作業自体がセッションログに残っていたので、コードも実行結果も丸ごと復元できました。ログを読む作業のログが残っているのは、こういうとき助かります。

当時のコードを今のログに流し直すと、方法の差と削除の差を分けられます。同じコードで新旧のログを比べれば削除のぶんだけが出るし、同じログに新旧のコードをかければ方法のぶんだけが出ます。

| | セッション | プロンプト |
|---|---|---|
| A 当時のコード × 当時のログ | 42 | 767 |
| B 当時のコード × 今のログ | 36 | 710 |
| C 今のコード × 今のログ | 36 | 537 |

3つとも同じ5プロジェクトに絞っています。A→B の -57 が削除で失われたぶん、B→C の -173 が数え方を直したぶんで、合わせて230。冒頭の内訳はこれです。

差の正体は、当時のコードが `isSidechain` を見ていなかったことでした。Subagent に投げた指示は、形式のうえではユーザーのプロンプトとして記録されます。弾かないと、AIが書いた文章が「自分が打ったもの」に混ざります。

### `type === "user"` だけでは足りない

素直に「`type` が `user` のエントリを拾えばいい」と思うと、4種類のノイズが入ります。

| 弾くもの | 中身 |
|---|---|
| `toolUseResult` があるエントリ | ツールの実行結果。`user` として記録される |
| `isMeta: true` | 内部メッセージ |
| `isSidechain: true` | Subagent 宛ての指示。自分が打ったものではない |
| `origin.kind` が `human` 以外 | タスク通知など |

もうひとつ、テキストのブロック自体がノイズのことがあります。IDEで開いているファイルを伝える `<ide_opened_file>`、選択範囲を伝える `<ide_selection>` は、プロンプトとは別のブロックとして同じエントリに入っています。手元では146件と22件ありました。ブロック単位で捨てれば、プロンプト本文は削れません。

なお `origin.kind` が入るのは 2.1.211 以降のログだけです。それより前には無いので、古いログまで遡るなら他の条件で判定する必要があります。手元の576件のうち43件が、この「フィールドが無い時代」のものでした。

### 抽出スクリプト

依存なしの Node スクリプトです。Claude Code 自体が Node で動くので、使っている人の手元には必ず Node があります。

```js
// extract-my-prompts.mjs — 自分のセッションログから、自分が打ったプロンプトだけを抜き出す
//   node extract-my-prompts.mjs > my-prompts.md
import fs from "node:fs";
import path from "node:path";
import os from "node:os";

const ROOT = path.join(os.homedir(), ".claude", "projects");

// プロンプトに見えて、そうではないブロック（IDEの状態通知・タスク通知・スラッシュコマンド展開）
const NOISE =
  /^\s*(?:<(system-reminder|ide_opened_file|ide_selection|task-notification|command-name|command-message|command-args)>[\s\S]*?<\/\1>\s*)+$/i;
// ツール実行を中断したときに Claude Code 自身が差し込む合成メッセージ
const SYNTHETIC = /^\s*\[(Request interrupted|Tool use was rejected)/;

for (const project of fs.readdirSync(ROOT)) {
  const dir = path.join(ROOT, project);
  if (!fs.statSync(dir).isDirectory()) continue;

  for (const file of fs.readdirSync(dir).filter((f) => f.endsWith(".jsonl"))) {
    for (const line of fs.readFileSync(path.join(dir, file), "utf8").split("\n")) {
      if (!line.trim()) continue;
      let e;
      try { e = JSON.parse(line); } catch { continue; }

      if (e.type !== "user") continue;              // assistant・内部イベントを捨てる
      if (e.isMeta) continue;                       // 内部メッセージ
      if (e.isSidechain) continue;                  // Subagent 宛ての指示。自分が打ったものではない
      if (e.toolUseResult !== undefined) continue;  // ツールの実行結果
      if (e.origin && e.origin.kind !== "human") continue; // 通知など（2.1.211 以降のみ）

      const c = e.message?.content;
      const blocks =
        typeof c === "string" ? [c]
        : Array.isArray(c) ? c.filter((b) => b.type === "text").map((b) => b.text)
        : [];
      const text = blocks
        .filter((t) => t.trim() && !NOISE.test(t) && !SYNTHETIC.test(t))
        .join("\n")
        .trim();
      if (!text) continue;

      // 区切りに ### を使わないこと。プロンプト本文に Markdown の見出しが普通に入っている
      console.log(`\n@@ ${project} / ${file.slice(0, 8)} / ${e.timestamp.slice(0, 10)}`);
      console.log(text);
    }
  }
}
```

```
node extract-my-prompts.mjs > my-prompts.md
```

**出力には顧客名・案件名・認証情報が普通に混ざります。** リポジトリに置かないでください。`.gitignore` に頼るより、そもそもリポジトリの外に出すほうが安全です。抽出結果を別のAIに読ませる場合はなおさら気をつけてください。

細かい話をもうひとつ。この数字には測定しているセッション自身のログも含まれます。走らせている間もログは書き込まれ続けるので、2回続けて実行すると少し増えます。記録に残すなら測定日をセットで書いておくのが無難です。

## 2. 「直近1ヶ月ぶん」は、たぶん自分で選んでいない

セッションログの保持期間は `settings.json` の `cleanupPeriodDays` で決まります。[公式スキーマ](https://json.schemastore.org/claude-code-settings.json)によると既定は30日で、削除は無警告です。

ここまでは既に書かれている話です。冒頭に書いた mtime の件は、この先を実測して出てきました。

手元のログを調べるとこうなっていました。

| | 値 |
|---|---|
| 現存ファイルの mtime の最古 | 29日前 |
| 現存ファイルの本文の最終メッセージの最古 | 57日前 |
| 現存ファイルの本文の最初のメッセージの最古 | 74日前 |

mtime の最古がちょうど29日前で、30日の境界に張り付いています。一方、最後にやりとりしたのが57日前というセッションが普通に残っている。最終メッセージ時刻で切っているなら、とっくに消えているはずです。

つまり長く resume し続けているセッションは、30日どころか2ヶ月以上前の会話を丸ごと抱えたまま生き延びます。逆に、短命で放置されたセッションは中身が新しくても消えます。「直近30日ぶんの会話が読める」ではなく「直近30日に触ったファイルが読める」でした。

これが効いてくるのは、ログを数えて何かを決めるときです。「直近1ヶ月ぶんのログを見た」と書くとき、その1ヶ月は自分で選んだ期間ではないかもしれないし、そもそも期間ですらないかもしれない。**「使っていない」ように見えるものが、単に窓の外にあるだけ**という可能性は潰しておいたほうがいいと思います。四半期に1回やるような作業は、この方法では構造的に候補に上がりません。

手元では90日に伸ばしました。

```json
{
  "cleanupPeriodDays": 90
}
```

ただし保持期間を伸ばすということは、ログに混ざっている顧客名や認証情報がローカルに残り続ける期間を伸ばすということでもあります。ディスクよりそちらのほうが判断材料になると思います。

### 実際に、根拠が1つ消えていた

最初の棚卸しのとき、AIが根拠として引用してきたプロンプトがいくつかありました。そのうち1つを今のログで検索したら、出てきませんでした。元のプロンプトが入っていたセッションのほうが先に消えたようです。

残っているのは、AIがそれを引用した6日前のログだけ。引用のほうが原文より長生きしている状態になっていました。ログを根拠に何かを決めるなら、決めた理由のほうを先に自分の手元へ書き出しておいたほうがよさそうです。

## で、棚卸しの結果はどうだったか

本題からは外れますが、そもそもこれを始めた動機のほうも簡単に書いておきます。

Skill の追加候補として `/commit-push-pr`・`/techdebt`・`/morning-sync` の3つをメモしてあったのですが、576件を検索して3つとも0回でした。存在しない需要を3つ書いていたことになります。

代わりにログにはっきり出ていたのは、メモのどこにも書いていなかった3つでした。

> 下記が別セッションで［AI］に引き継げるように提案してもらった内容！

引き継ぎ書を手で書いてコピペしていた（セッションを分けて作業するのが定着していた）。

> geminiにレビューしてもらったよ。
> 妥当か判断よろしく！

「レビュー」という語が17回。外部AIのレビューを貼って、採否を毎回ゼロから判定していた。

> ちなみにこのgmailでの一覧の設定（プロジェクト作成から認証まで）、
> 正直なんのためにやったのかピンと来ていないので、
> すごくわかりやすく説明してほしい。なぜ必要だったのか。

外部サービスの初期設定の伴走。これが一番回数が多くて、しかも「手順は終わったが理解していない」という状態が言語化されていました。

外れ方が対称ではないのが面白いところで、存在しない需要を3つ書いていた（偽陽性）だけでなく、毎週やっている作業を3つ取りこぼしていた（偽陰性）。記憶に残るのは珍しくて難しかった作業のほうで、手順化すべきなのは退屈で繰り返しているほうでした。

ついでに白状しておくと、このとき候補リストから消したのは2件だけでした。`/commit-push-pr` は0回のまま残っていて、今も候補欄に居座っています。せっかく検出したのに3分の1を取りこぼしていました。

## まとめ

- 会話は `~/.claude/projects/` に全文残っている。Claude Code を使っている人全員の手元にある
- `type === "user"` だけでは足りない。`toolUseResult` / `isMeta` / `isSidechain` / `origin.kind` の4つを弾く。特に `isSidechain` を落とすと、AIが書いた文章が自分のプロンプトとして数えられる
- 出力には顧客名も認証情報も混ざる。リポジトリの外に出す
- 数字を出すときは「どう数えたか」も一緒に残す。手元では、方法の差が削除の差の3倍あった
- 保持期間は既定30日。ただし判定は mtime なので、「直近30日ぶんの会話」ではない。resume し続けたセッションは2ヶ月以上前の会話を抱えたまま残る

ログを読むと勘より正確なことが分かる、というところまでは想像どおりでした。想像していなかったのは、そのログのほうも黙って形を変えていたことです。
