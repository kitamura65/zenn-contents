個人開発中のプロダクトで、ユーザーの生の声(「〜が欲しい」「〜が面倒」)を集めてくるデータ収集先を新しく増やす作業をしていました。候補サイトが十数個あったので、AIに「まずrobots.txtと利用規約を一通りチェックしてきて」とお願いして回ってもらったのですが、その過程で色々と気づきがあったので、実際に手を動かして確認した内容の記録として共有します。

## 1. 発端: 「robots.txtだけ見ればいい」時代は終わっていた

(そもそもrobots.txtって何、という方向けに一言だけ補足すると、`https://example.com/robots.txt`のように各サイトのルート直下に置かれた設定ファイルで、「このURLはクロールしていい/ダメ」をサイト側がクローラーに向けて宣言するためのものです。誰でも読める前提で各サイトが自分で公開しているファイルなので、中身を確認すること自体には何の問題もありません。)

最初は単純に、各サイトの`robots.txt`で`ClaudeBot`等のAIクローラーが許可されているかだけ確認すればいいと思っていました。ところが実際に十数サイト分の結果を並べてもらうと、`robots.txt`がクリーンでも**利用規約側でAI利用そのものを禁止している**サイトがいくつも出てきました。

## 2. 規約側でAIを名指しで禁止しているサイトがあった

一番はっきりしていたのが、プログラミングQ&Aサイトのteratailです。`robots.txt`にAIクローラーへの個別ブロックは無かったのですが、利用規約を確認してもらったところ、こんな条項がありました。

> 当社の事前の書面による許諾なく、本サービス上のデータ(投稿データを含みます。)を、情報解析、人工知能(AI)の開発、機械学習、または学習用データセットの作成等の目的で、収集、複製、利用し、または第三者に提供する行為(第7条第21号)

「情報解析」「人工知能(AI)の開発」「学習用データセットの作成」と、AI用途をピンポイントで名指しして禁止していました。robots.txt側だけ見て「ブロックされてないから大丈夫」と判断していたら、そのまま見落としていたところです。

## 3. robots.txt側も、単なる`Disallow: /`じゃなくなってきている

規約とは逆に、`robots.txt`側で徹底しているサイトもありました。クラウドソーシングのクラウドワークスは、こんな見出し付きでAIクローラーをブロックしています。

```
# AI学習用クローラーのクロールを拒否
# https://developers.facebook.com/docs/sharing/webmasters/web-crawlers/
# https://developers.openai.com/api/docs/bots
# https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler
User-agent: meta-externalagent
User-agent: GPTBot
User-agent: ClaudeBot
Disallow: /
```

Q&AサイトのOKWAVEはさらに徹底していて、`robots.txt`に列挙された`User-agent`が150個。`anthropic-ai`・`ClaudeBot`・`Claude-User`・`Claude-SearchBot`・`Claude-Web`・`Claude-Code`と、Claude関連だけで5種類くらい個別に名指しでブロックされていました。読売新聞の「発言小町」に至っては、AIクローラーだけでなく`curl`・`wget`・`Scrapy`・`Mechanize`といった汎用ツールのUser-Agentまで個別に`Disallow: /`していて、これは実際に自分でも確認しましたが徹底ぶりに笑ってしまいました。

この時点で「`robots.txt`」と「利用規約」の両方を毎回セットで確認する運用に切り替えました。どちらか一方がクリーンでも、もう一方で塞がれているケースが普通にあるからです。実際、この期間に候補として見た十数サイトのうち、規約・robots.txtの両方をクリアできたのは1〜2割程度でした(どのサイトが通ったかは今回は伏せておきます)。

## 4. 「事前の書面による許諾」を、フリーランスの個人開発者はどう取ればいいのか

teratailの条項には「当社の事前の書面による許諾なく」という留保がついています。理屈の上では、許諾さえ取れれば道は開いているわけです。ただ、フリーランスで一人で開発しているプロダクトにとって、これが現実的な選択肢になるかというと話は別です。

実際、似たような形で正規のルートを試したことがあります。別の候補として、RedditのAPIアクセスを申請したことがあるのですが、返ってきたのは具体的な理由に一切触れない定型文の却下通知でした。個人開発者が公式サポートに問い合わせても、企業のように担当者がついて交渉できるわけではなく、定型文の壁に当たってそれきり、というのが実情です。

顧問弁護士がいるわけでもないので、「情報解析、人工知能(AI)の開発、機械学習」といった条文の文言を自分で読んで、自分で「これは該当するかどうか」を判断するしかありません。判断を誤れば、その責任を負うのも自分一人です。同情してほしい話というより、個人でデータを扱う以上は避けられない役割だと思っていますが、規約を1つずつ読みながら「法務部がいる会社なら、この条文をどう解釈するんだろう」と何度か考えました。

## 5. 余談: 一番「問題なさそう」に見えたサイトで起きたこと

teratailやOKWAVEのような明確な拒否が続く中、一つ問題なさそうなサイトもありました。robots.txtは`ClaudeBot`を含む主要クローラーに`Allow`を明示していて、利用規約にもAI収集を禁止する条項は見当たりませんでした。

```
User-Agent: ClaudeBot
Allow: /

User-Agent: Claude-User
Allow: /
```

ただ、実装に入る直前に念のため生のHTMLをAIにcurlで取得してもらったところ、投稿データが一切含まれていないことが分かりました。レスポンスヘッダーの`Content-Security-Policy`を見ると、外部のBaaS(Backend as a Service)のドメインが`connect-src`に入っていて、実際にはブラウザ上のJavaScriptがBaaSに直接データを取りに行く構成のようでした。「規約もrobots.txtもクリーンでも、実際のHTTPレスポンスは別に確認しないと分からない」という話として、この時点でメモに残していました。

ところが、この記事を書くために念のためもう一度同じ確認をしてもらったところ、今度は投稿タイトルがそのまま`<h3>`タグの中に入っていて、生のHTMLに投稿データが普通に含まれていました。3種類の異なるUser-Agentで試しても結果は同じ。レスポンス自体も0.3秒ほどで返ってきていたので、ストリーミングでの取りこぼしのような単純な話でもなさそうでした。結局、数日前の「データが入っていなかった」という確認結果が何だったのかは特定できませんでした。サイト側の実装が変わったのか、前回の確認手順に何か問題があったのか、判断できる材料は残っていません。

一次情報は一度確認したら終わりではなく、時間が経てば状況も、下手をすれば自分自身の確認結果すら変わりうる。ここまで書いてきた、規約とrobots.txtを1つずつ調べてきた話の教訓と根っこは同じだと思ったので、短いエピソードとして添えておきます。

## まとめ

- 新しいデータ収集先を探す中で、`robots.txt`がクリーンでも利用規約でAI利用を明示的に禁止しているサイト(teratail等)、逆に`robots.txt`側でAIクローラーを徹底的にブロックしているサイト(クラウドワークス・OKWAVE・発言小町等)が、国内のUGCサイトで目立って増えていることが分かった
- 「許可されているか」は、`robots.txt`・利用規約のどちらか片方だけでは判断できず、両方を都度セットで確認する必要がある。候補として見た十数サイトのうち、両方クリアできたのは1〜2割程度だった
- 「事前の書面による許諾」のような条文があっても、フリーランスの個人開発では正規ルートでの許諾取得自体のハードルが高い(定型文で却下されて終わることもある)。条文の解釈も、その責任を負うのも結局は自分一人になる
- おまけとして、規約もrobots.txtもクリーンに見えたサイトでも、実際のHTTPレスポンスを見ないと分からない落とし穴があった。しかもその確認結果自体、後で確認し直したら再現しなかった。一次情報は一度確認して終わりにせず、都度確認し直すのが安全
